# NDS Agent 协作文档中心（测试 Agent / 开发 Agent 共用）

> 本目录集中存放所有用于 **外部开发 AI ↔ 内部测试 AI** 协作的文档。
> 设计原则：稳定内容（SOP、入职必读）与易变内容（回执、当前指令）分开，
> 避免"换机器/换 Agent 就重喂一遍全部历史"。

## 文档地图

| 文档 | 性质 | 什么时候读 |
|------|------|-----------|
| [onboarding.md](onboarding.md) | **稳定**·入职必读 | 新建测试 Agent 时，第一份要读的文档 |
| [env_sop.md](env_sop.md) | **稳定**·标准作业流程 | **每次换新机器**时，照着从头走一遍 |
| [nds_company_validation_task.md](nds_company_validation_task.md) | **易变**·主对话文件 | 日常执行时：第 10 节取最新指令，第 9 节写回执 |
| [../nds_design.md](../nds_design.md) | 稳定·技术设计 | 需要理解三层架构/方案背景时 |

## 两个常见场景的标准流程

### 场景 1：测试 Agent 挂了，新建一个

```
1. 新 Agent 读 onboarding.md（项目目标/协作机制/守则/踩坑，约 10 分钟）
2. 读主对话文件第 10 节的【最新一条指令】（当前任务以它为准）
3. 按指令执行，回执追加到主对话文件第 9 节
不需要重喂历史——历史都在主对话文件的 git 记录里，需要时再查。
```

### 场景 2：机器被占用 / 环境不稳定，换新机器

```
1. 新 Agent（或旧 Agent）按 env_sop.md 从阶段 0 走到阶段 5
   （体检 → 部署代码 → 部署 UMDK → 编译 → 产物验证）
2. 体检报告 + 每阶段输出回传到主对话文件第 9 节
3. 外部 AI 根据报告更新《当前环境速览》（onboarding.md 第 4 节），
   并下发后续验证指令（注意：历史问题在新环境要当作"可能已消失"重新验证）
```

## 当前环境速览 → 看 onboarding.md 第 4 节
## 当前任务 → 看主对话文件第 10 节最后一条指令

（以上两处由外部开发 AI 在每次环境变更/批次推进时更新）
