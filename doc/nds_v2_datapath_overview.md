## 二、一次 I/O 的数据流向

```
读命令（SSD → HBM）                          写命令（HBM → SSD）
────────────────────────                     ────────────────────────
① initiator 经 TCP 下发读命令                ① initiator 经 TCP 下发写命令
② target 读 SSD                              ② target post WR（tjetty=RA jetty）
③ target post WR（tjetty=RA jetty）          ③ 远端读 HBM → 数据直达 target
   远端写 HBM                                 缓冲区（CPU 不参与）
④ 数据 SSD → target → HBM                    ④ target 写 SSD
⑤ 完成回包 → initiator                       ⑤ 完成回包 → initiator
```

- 数据搬运全部由 URMA 网卡按 WR 直接完成，**不经过 initiator 的 CPU、不做内存中转**。
- 控制面（命令/参数）与数据面（HBM 数据）走不同通道，用不同 jetty，互不干扰。

## 三、关键修复在链路中的位置

| 修复 | 在链路中的位置 | 解决的问题 |
|---|---|---|
| **chip1 设备选择** | UB 网络层（两侧设备选择） | RA 域地址只经 chip1 可达；chip0 会访问超时 |
| **双 jetty 分流**（wire v4） | initiator HELLO 发布 + target 数据面选路 | host 内存（胶囊）与 HBM 属于不同访问域，需各自匹配的 jetty |
| **整块注册 + 引用计数** | NPU 节点 RA/libnds 层 | 注册范围（4KB）与发布范围（64KB）不一致，导致偏移访问被远端拒绝 |
