## 三、本轮解决的核心问题（根因链）

本轮把"数据面远端访问失败"一路定位到三个独立的根因并全部修复：

| # | 根因 | 判决依据 | 修复 |
|---|---|---|---|
| 1 | **chip 路由**：RA 域地址只能经 chip1（udmac1*）访问，target 默认走 chip0 | 设备扫描：chip0 全失败、chip1 全通过；裸探针单变量复现 | 两侧指定 chip1 设备 |
| 2 | **双域访问语义**：胶囊/控制数据在 host 内存（设备域），HBM 数据在 RA 域；用一把"钥匙"（单一 jetty）打不开两种门 | 同一进程内：host 段成功、RA 段失败；换 tjetty 即成功/失败互换 | **双 jetty 分流**：控制走 host jetty，HBM 数据走 RA jetty，按段 eid 自动路由（wire v4 正式化） |
| 3 | **注册范围与发布范围不一致**：provider 只注册本次 I/O 的 4KB，却对外发布整块 64KB 段描述 | 逐条 WR 台账：偏移 0 全成功、偏移 >0 全被远端 abort；整块注册后并发零错误 | **整块注册 + 引用计数**：按分配块注册一次，I/O 仅计数 |

> 三个问题叠加造成了此前的"单发正常、并发必败"（-b 1 只命中偏移 0，-b N 的 N−1 条落在未注册区）。

## 四、V2 最终形态

1. **chip1 配置**：两侧使用 udmac1d1e2（RA eid 仅经 chip1 可达）。
2. **双 jetty 分流**（wire v4）：主 jetty 为 RA jetty；另发布设备域 host jetty；target 按远端段 eid 自动选择。
3. **整块注册**：provider 按分配块注册一次，per-I/O 引用计数；发布信息与注册范围严格一致。
4. **无临时开关**：此前所有调试用 env 门控与 hack 已全部删除。
