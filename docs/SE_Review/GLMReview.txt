验证 #8（target 排水）——最核心

场景 A：高压下 kill initiator（20–50 轮）
1. target 起后 initiator 跑 urma_perf/fio，多 q 多深度，保证断连瞬间 target 有 PULLING/PUSHING 在途写
2. initiator 侧 kill -9（不要优雅退出）
3. target 观察：
   - 日志不应出现 drain deadline exceeded（出现就说明排空判定有洞，把 pending_wr/pending_msgs 数值发我）
   - qpair 秒级消失，iobuf 池回到基线（修前是 UAF：往已归还 buffer 写）
4. 每轮记 target RSS，20+ 轮应平稳

场景 B：ASAN 版 target 跑 3–5 轮场景 A（最有说服力）
- ./configure --enable-asan 重建 target，重复 kill。修前必报 use-after-free，修后应干净退出

验证 #4（initiator 重连）

场景 C：循环 kill target（20+ 轮）
1. initiator 长跑，循环：kill -9 target → 等重连 → 重启 target → I/O 恢复 → 再 kill

场景 D：数据正确性——重连后首轮 I/O 用 fio --verify=md5，确认旧连接 CR 没污染新连接。
