# target 打点按轮清零：以"新连接进入"为轮边界 dump+reset

target 是长驻进程，最初打点计数器从 nvmf_tgt 启动起一直累加，多轮 urma_perf（不同
iosize）的数据混在一起无法按轮分析。2026-09-09 决定：在 accept 每条新连接时，先把累计
数据 dump 一份再清零——urma_perf 每轮 burst 建立 1 admin + N IO 条连接，工作 I/O 在全部
连接就绪后才开始，所以 burst 内多次 reset 都发生在测量之前，setup 噪音也被清掉，轮边界
精确且零手工步骤。日志形态：每轮开始处一条 `---- 新连接进入 ----` + 上一轮最终计时。

## Considered Options

- 每轮重启 nvmf_tgt —— 被否：要重做整个接管/RPC 流程，太重。
- 加自定义 RPC 清零方法 —— 被否：多一个手工步骤，忘记调用就又混轮。
- 周期 dump 改为 snapshot+reset（按窗口出数）—— 被否：窗口与轮边界不齐，跨轮 I/O
  会落进同一窗口；且改变 dump 语义影响既有观察习惯。

## Consequences

- 日志分析以 `---- 新连接进入 ----` 为分界；周期 dump 的数字是"本轮开始至今"的累计，
  不是进程启动至今。
- 运行中途异常重连也会触发清零（会留下一条 dump 标记，数据可见但断轮）。
