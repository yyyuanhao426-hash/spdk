# 第 1 讲：对象——档案袋、指针与队列对

> **本讲只讲一件事**：SPDK 把"连接这件事"记在哪些盒子里。
>
> 前置：会读 C 的 struct、指针即可。

---

## 一图

```
                    ┌───────────────────────────────────┐
                    │  struct spdk_nvme_ctrlr           │
                    │  ┌─────────────────────────────┐  │
   连谁？ ─────────▶│  │ trid : 地址（IP/端口/nqn）   │  │
   什么参数？ ─────▶│  │ opts : 超时/队列深度/...     │  │

                                    │ 指针

                    ┌───────────────────────────────┐
                    │  struct spdk_nvme_qpair        │
                    │  ┌────────────┐ ┌───────────┐  │
     放请求 ───────▶│  │ SQ 提交队列 │ │ CQ 完成队列│◀── 取结果
```

## 1.1 struct 就是一个档案袋

```c
struct spdk_nvme_ctrlr {
        struct spdk_nvme_transport_id trid;   /* 连谁 */
        struct spdk_nvme_ctrlr_opts   opts;   /* 什么参数 */
        struct spdk_nvme_qpair       *adminq; /* 办手续的通道 */
        int                           state;  /* 走到第几步 */
        bool                          is_failed;
        /* ……还有 Identify 回来的资料 cdata 等 */
};
```

为什么要这个袋子？因为**流程要跨很多轮**：

- 第 1 轮记下"要连 192.168.1.2:4420"，第 5 轮还要用 → 必须存。
- 第 3 轮把进度改成"等 Connect 回应"，第 4 轮要读 → 必须存。

**没有袋子，这些信息无处安放。**

---

## 1.2 指针 vs 内嵌：袋子里装"地址"还是"实物"

```c
struct A {
        struct B  b;    /* 内嵌：b 和 A 在同一块内存里，A 生 b 生 */
        struct C *c;    /* 指针：c 指向别处，A 和 C 可以分开生、分开死 */
};
```

在 `ctrlr` 里：

- `trid`、`opts`、`state` 是**内嵌**的（跟着 ctrlr 一起分配）。
- `adminq` 是**指针**：qpair 是单独 `calloc` 出来的另一块内存。

画成内存图：

```
ctrlr 这块内存                      qpair 那块内存
┌──────────────────────┐           ┌──────────────────┐
│ trid   [ ...... ]    │           │ SQ / CQ 数组      │
│ opts   [ ...... ]    │           │ id = 0           │
│ adminq ──────────────┼──────────▶│ ...              │
│ state  = 1           │           └──────────────────┘
└──────────────────────┘
```

**记住**：日志里 `qpair=0xfffb...` 打印的就是右边这个地址；同一个 ctrlr 的 adminq 地址永远不变。

---

## 1.3 qpair：两个窗口

qpair 是"队列对"，里面有两张表：

```
   你（initiator）                          对端（target）
        │                                        │
        │  1. 把请求写进 SQ                       │
        ├────────────── SQ ─────────────────────▶│
        │  2. 敲一下门铃（doorbell）              │
        │                                        │  3. 对端处理
        │  4. 对端把结果写回 CQ                   │
        │◀───────────── CQ ──────────────────────┤
        │  5. 你来 CQ 取结果                      │
        ▼
```

生活类比：奶茶店。SQ 是下单口，CQ 是取餐口。**放下单子就走，不站着等**；过一会儿来取餐口看有没有你的。

### qid 的两种身份

| qid | 名字 | 用途 | 典型日志 |
|---|---|---|---|
| **0** | admin qpair | 只办手续：Connect、Identify、设参数 | `qid:0` |
| **1..N** | io qpair | 搬数据（读写），也包括心跳/探测 | `qid:1` |

> 你看到的 `qid:1` 失败，**不是**"第一个 IO 请求失败"，而是"第二条通道建不起来"。

## 1.4 谁拥有谁

```
spdk_nvme_probe_ctx（差旅袋，见 03 讲）
  │
  └─ init_ctrlrs（待办清单）
        │
        ▼
     [ctrlr] ──▶ adminq（qid=0）
        │
        └─ active_io_qpairs ──▶ qid=1, qid=2, ...
```

- `probe_ctx` 拥有"待办清单"。
- `ctrlr` 拥有 `adminq` 和所有 io qpair。
- `attach_cb` 把 `ctrlr` 交给应用后，**应用才拥有使用权**（但内存仍由 SPDK 管）。

---

## 1.5 生命周期

```
calloc(ctrlr)            ← probe 阶段，只分配，不联网
  │
  ├─ state 一路推进      ← 每一轮 poll 走一步（见 04 讲）
  │
  ├─ READY               ← attach_cb 把 ctrlr 交给应用
  │
  ├─ 应用用              ← alloc io qpair、读写
  │
  └─ detach/destruct     ← 释放
```

失败时走 `attach_fail_cb`，然后 `ctrlr` 被异步销毁（见 07 讲"善后三件套"）。

---

## 常见误解

| 误解 | 实际 |
|---|---|
| "ctrlr 是 control 的缩写" | 是 **controller**（控制器），不是 control |
| "qpair 是一个队列" | 是**一对**：SQ + CQ |
| "qid=1 是第一个请求" | 是编号为 1 的**通道**（通常是第一条 io qpair） |
| "日志里的 qpair 地址会变" | 同一个 ctrlr 的 adminq 地址固定；不同 ctrlr 当然不同 |
| "ctrlr 里的东西都内嵌" | `adminq` 是指针，指向另一块内存 |
