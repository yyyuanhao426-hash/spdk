# 第 6 讲：rc 全书——同一个数字，为什么到处变脸

> **本讲只讲一件事**：rc 在不同层有不同的含义和翻译规则；只看最上层会被骗，根因永远在最下面。
>
> 前置：04、05。

---

## 一图：一条错误的"上行翻译"之路

```
URMA 硬件/对端
   │  CR status=10（RNR 重试耗尽）
   ▼
nvme_urma_process_capsule_cr_inner
   │  一律翻成 -EIO(-5)          ← 信息在这里丢失
   ▼
nvme_urma_qpair_process_completions  fail:
   │  统一翻成 -ENXIO(-6)        ← 标准"通道已拆"信号
   ▼
nvme_qpair.c:914
   │  打印 "CQ transport error -6"
   │  如果是 admin：ctrlr 判死
   ▼
nvme_ctrlr_poll_internal
   │  rc != 0 → attach_fail_cb(rc)
   ▼
应用层
   │  可能再补一个 -19（wrapper）
   ▼
你看到的日志
```

**规律：越往上，信息越少。** 所以读日志要从下往上找第一手证据。

## 6.1 五类值

| 值 | 名字 | 谁产生 | 含义 | 是错误吗 |
|---|---|---|---|---|
| `0` | success | 各层 | 成功 | 否 |
| 负 errno | 系统/实现错误 | 各层 | 真实错误 | 是 |
| `-EAGAIN` (-11) | 暂时没有 | 轮询/状态机 | **没干完** | **否** |
| `-ENXIO` (-6) | 通道已拆 | 传输层 fail 出口 | **信号** | 是信号，不是根因 |
| `-1` | 状态机失败 | `process_init` ERROR 分支 | **不是 errno** | 是 |
| `-125` | 我放弃了 | `wait_for_completion_poll` | 超时 | 是，但不是对端报的 |

### 常用 errno 速查

| 值 | 名字 | 在本项目里的典型含义 |
|---|---|---|
| -2 | ENOENT | 裸 errno 泄漏：段注册/连接失败（**不代表"文件不存在"**） |
| -5 | EIO | 传输层"垃圾桶"：CR 非成功 / Connect 完成错误 |
| -6 | ENXIO | qpair 已拆（SPDK 内部信号） |
| -11 | EAGAIN | 轮询层是油门；**阻塞收发层是 5s 超时** |
| -12 | ENOMEM | 内存不足 |
| -16 | EBUSY | 连接正在被另一轮使用 |
| -19 | ENODEV | 设备打开失败；**wrapper 也用它表示"probe 没交钥匙"** |
| -22 | EINVAL | 参数不合法 |
| -90 | EMSGSIZE | inline 容量不够等 |
| -95 | ENOTSUP | 不支持（bonding、加速内存等） |
| -104 | ECONNRESET | 对端断开 / socket EOF |
| -110 | ETIMEDOUT | TCP 连接超时 |
| -111 | ECONNREFUSED | 目标端口没在监听 |
| -125 | ECANCELED | 我方的截止时间到了 |

## 6.2 每一层该报什么（读代码时的心理模型）

| 层 | 它"知道"什么 | 它该怎么报 |
|---|---|---|
| URMA 传输层 | CR 的 status、socket 状态 | CR 的 `status=` 打在 `cr_error` 行；对外统一 `-ENXIO` |
| `nvme_qpair.c` | qpair 状态 | 打 `-6`；admin 失败时判死 ctrlr |
| 状态机 | 走到哪一步 | `-1`（异步收尾）或透传同步 rc |
| 应用层 | 业务语义 | 自己补码（如 -19） |

**读日志时先问：这一行是哪一层打的？** 第 07 讲有按文件/函数反查的表。

## 6.3 三个最常见的误读

### 误读一："Operation not permitted" = 权限问题

```
nvme.c:834 Failed to attach nvme ctrlr: ... Operation not permitted
```

这一行来自默认的 `attach_fail_cb`：

```c
SPDK_ERRLOG("Failed to attach nvme ctrlr: ... %s\n", spdk_strerror(-rc));
```

当 `rc = -1` 时，`spdk_strerror(1)` 打印 **EPERM（Operation not permitted）**。
**`-1` 不是 errno**，它只是"状态机到了 ERROR"。所以这行文字纯粹是翻译巧合。

### 误读二："rc=-19 是内核说没设备"

wrapper 里：

```cpp
rc = spdk_nvme_probe(...);
if (rc != 0) return rc;
return info->ctrlr != nullptr ? 0 : -ENODEV;   /* ← 自己补的 */
```

`-19` 是应用层说"probe 结束了，但没交钥匙"。

### 误读三："sc 8 是对端拒绝"

```
Connect command completed with error: sct 0, sc 8
```

`sc = 8 = ABORTED_SQ_DELETION`，是**本地因为拆队列而中止了这条命令**，不是对端的错误码。
它通常出现在"已经有别的错误把 qpair 拆了，Connect 顺带被中止"的场景。

## 6.4 `-1` 与 `-125` 的区别

```
4505 error: -1,  state: 57   → 异步失败/超时收尾：根因在上一轮
4505 error: -125, state: ?   → 我方截止时间到了（Connect 场景）
```

两者都不是对端直接报的错，但：

- `-1` 是"状态机已经在 ERROR 里，我这次只是来报到的"；
- `-125` 是"我等到期限，自己放弃的"。

---

## 6.5 一张"同样数字、不同层"对照

| 数字 | 在轮询层 | 在阻塞收发层 | 在应用层 |
|---|---|---|---|
| `-11` | 没干完，再来 | **5 秒超时** | — |
| `-19` | 设备打开失败 | — | **probe 没交钥匙** |
| `-5` | CR 非成功 | Connect 完成错误 | — |
| `-6` | 通道已拆 | — | alloc 失败 |

**同一个数字在不同层完全可能不是一回事。** 这就是为什么讲义一直强调"先定位是哪一层"。
