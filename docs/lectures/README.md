## 全课唯一需要先记住的模型：六样东西

一次 attach，无论代码多长，只有六样东西在动：

| # | 物件 | 是什么 | 坏掉时你会看到 |
|---|---|---|---|
| 1 | **ctrlr** | 档案袋：连谁、什么参数、走到哪 | 指针为 NULL、构造失败 |
| 2 | **state** | 进度，0～58 | `Ctrlr is in error state` |
| 3 | **qpair** | 通道：SQ + CQ，qid 0 是管理，≥1 是数据 | `CQ transport error -6` |
| 4 | **loop** | `while` + `poll_async`，一圈圈推 | `-EAGAIN` 永远结束不了 |
| 5 | **deadline** | Connect 500ms、admin 命令超时 | `rc=-125` / `Initialization timed out` |
| 6 | **exits** | `attach_cb` / `attach_fail_cb`，互斥 | 只来其一 |

之后的每一讲，都是这六样东西的展开。

## 全课约定

### rc 的五类（先眼熟，06 讲展开）

| 值 | 含义 | 是错误吗 |
|---|---|---|
| `0` | 成功 | 否 |
| 负 errno（-2/-5/-19/-104/-110…） | 真实错误 | 是 |
| `-EAGAIN` (-11) | "还没好"（轮询层） | **否，是油门** |
| `-ENXIO` (-6) | "通道已拆"（信号） | 是信号，不是根因 |
| `-1` | "状态机到终点"（不是 errno） | 是 |
| `-125` (-ECANCELED) | "我自己放弃（超时）" | 是，但不是对端报的 |

> 注意：`-EAGAIN` 在**阻塞收发**层（如 hello 的 socket 超时）含义不同，见 05 讲。

### 命名约定

- `_cb` = callback = **函数**（你提供，SPDK 调）
- `_ctx` = context = **袋子**（装数据）
- `spdk_` 前缀 = 公开 API；`nvme_` 前缀 = 库内部
- `trid` = transport id = 地址；`ctrlr` = controller；`qpair` = queue pair

### 日志里的 stage（URMA 自定义）

| stage | 含义 |
|---|---|
| `cr_error` | 收到完成记录（CR）且状态非 0 |
| `fatal` | 传输层决定拆 qpair |
| `recv_post` | 接收 WR 投递失败 |

## 学习建议

- **第一遍**：只读图和"常见误解"，不求细节。
- **第二遍**：对着真实代码打开对应函数读一遍。
- **第三遍**：拿一屏真实日志，按 07 讲的五问法走一遍。
- 卡住时：回到 08 速查卡，先定位"在哪一幕"，再回头读对应讲。
